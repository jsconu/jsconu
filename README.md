### Why this work is different

I'm not trying to replace project-management software with a chatbot.

I'm interested in the operating layer above the tools teams already use: connecting fragmented signals from project systems, communication, meetings, and documents; maintaining state over time; separating evidence from inference; surfacing decisions that need attention; and letting automation act only inside explicit guardrails.

That work draws directly on 10+ years leading SaaS, transformation, M&A, CX, and operational programs in enterprise environments.

### How I build with AI

I use coding agents heavily. I don't treat that as a substitute for judgment.

My role is to define the product and operating model, frame the domain, set acceptance criteria, review architecture and failure modes, design evaluations, challenge unsafe or misleading behavior, prioritize tradeoffs, and validate whether the system actually solves the business problem.

The goal is not to prove I can hand-type every line of implementation. The goal is to demonstrate that I can **lead AI-enabled product and program work with enough technical depth to interrogate what the system is doing and why.**
